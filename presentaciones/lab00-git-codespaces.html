¿Qué hace un Compilador?

Un compilador traduce representaciones textuales de alto nivel a secuencias de instrucciones binarias entendibles por la CPU.

token_scanner.c (Texto ASCII) → gcc → token_scanner (Binario ELF x86-64)

Compilación Rigurosa con GCC

En ingeniería de compiladores no aceptamos advertencias (*warnings*):


# Compilar con todas las advertencias activadas
gcc -Wall -Wextra token_scanner.c -o token_scanner

# Ejecutar el binario generado
./token_scanner
  • -Wall: Activa advertencias sobre construcciones ambiguas.
  • -Wextra: Agrega comprobaciones estrictas de tipos y variables no usadas.
  • -o: Especifica el nombre del archivo de salida.

¿Qué se sube a Git y qué NO?

NUNCA subas archivos binarios o ejecutables a GitHub.

  • ✓ SÍ se sube: .c, .h, Makefile, .gitignore, README.md.
  • ✗ NO se sube: *.o, *.out, ejecutables sin extensión, archivos temporales.

El Archivo .gitignore

Le indica a Git qué archivos debe ignorar por completo:


# Crear o agregar el binario a la lista de exclusión
echo "token_scanner" >> .gitignore

# Comprobar que git ya no intenta rastrear el ejecutable
git status

El Flujo de Trabajo Diario

  1. Editar el código fuente (token_scanner.c).
  2. Compilar y probar localmente (gcc ... && ./token_scanner).
  3. git status (Verificar cambios).
  4. git add token_scanner.c .gitignore (Preparar fuentes).
  5. git commit -m "feat: agrega token_suma al scanner" (Documentar).
  6. git push origin main (Publicar en GitHub).

Práctica de Hoy en el Laboratorio

  1. Abrir tu Codespace / terminal de Linux.
  2. Escribir el código en C de token_scanner.c.
  3. Compilarlo y ejecutarlo con gcc -Wall -Wextra.
  4. Añadir el token de suma (+) y verificar que no arroje *warnings*.
  5. Configurar .gitignore y hacer tu primer push a GitHub.
